## 3. Assign types and charge

Use the bead types in the configured core ITP. Use documented chemical/size/polarity/label precedents, including substituent effects. Verify every chosen name exists. Do not borrow a later extension silently. Assign net charge from intended chemical state and compatible documented models, not arbitrary sums of atomistic partial charges. Record a source-backed assignment for every bead.

Type each bead by this ladder with `design_bead`, which records the rung used and what each earlier rung found. The typing task message already lists, per bead, the rung-1 precedents and the Table 24/25 rows that match the bead's chemical group, with the `PATH:LOCATOR` to cite (`design_evidence` repeats this for any atoms). `design_match` reports exact bead matches from all indexes, grouped by type.

1. The same fragment typed in an indexed model or Bible entry → `transferred`. Same fragment means the same heavy atoms in the same bonding context, checked in the source's mapping file (`.ndx`/`.map`) or Bible entry: the source bead must hold what your bead holds, no fewer and no more atoms. Copy the type of that bead, not of a neighbouring one. A type taken from a source bead with other atoms (for example the SN3ar of a C–O–C bead given to a lone ether oxygen) is not rung 1; go to rung 2. Record it as `design_bead` with `rung` 1 and `source_bead` `REF_ID:BEAD` on an opened reference: the tool compares the fragment signatures and copies the type. The signature compares the bead's own atoms and the bonds leaving it, not the atoms beyond them (Bible fragments do not record those). When the neighbours differ in a way the SI proximity rules cover (conjugation, induction, local dipole), say so in the rationale, or use rung 2. **When precedents disagree on the type** (the evidence block says so, with each type's count, how many of its precedents have the same surroundings as your bead, the atoms one bond outside it, and which type the partition's own source uses): choose, in this order, (1) the type with the most precedents that have the same surroundings as your bead (count only those; when no precedent has them, count all); (2) only to break a tie, the type of the partition's own source reference (beads that hold identical fragments in this molecule take one type); (3) a Table 24/25 or Alessandri Table 1 row for this group and size can confirm the choice. The evidence names the partition's source for the bead and its type, and the type this order gives. Name the types you did not use and why in the rationale. Do not pick a type only because it appears first.
2. The nearest documented chemical group (Souza SI Table 24/25 [MEV:souza-si:T24:*, MEV:souza-si:T25:*]; for the bead's size, the building blocks of Alessandri 2022 Table 1 [MEV:alessandri:T1:*], each with an example model to open), refined with the SI proximity rules (section C2: inductive/conjugation, local dipole, internal H-bonds, resolution [MEV:souza-si:C2:rule1-induction ... rule4-resolution]) → `adapted`, naming the group and the rule applied (`group`, `rule`, `sources` as `PATH:LOCATOR`). If rung 1 was available, `rung1_rejection` says why it was not used.
3. No matching group: select a type of the bead's size (the evidence states it: T, S or R) from the partitioning data of the isolated fragment, as the SI prescribes (Souza SI section C introduction, step 2, p. 35; Supplementary Tables 17–19 [MEV:souza-si:T17, T18, T19 for R, S, T beads]) → `adapted`, citing the table and values (`table`, `values`, `rung2_finding`).
4. Only if all three fail: `unresolved`. Record what each rung found with `design_note` (`limitation`); the model is `blocked`.

A type from rung 2 or 3 for chemistry with no direct precedent (for example a carbonate or a conjugated lactone) is a provisional type: it does not block execution, but it must be flagged `provisional_type` (`provisional`) and listed in the report.
